The missionLa mission

Here’s the big picture before you dive into the rules.

La vue d’ensemble avant de plonger dans les règles.

Exaltemps Solidaire is a hackathon with a purpose: delivering real IT work to associations that don’t have any IT expertise. We’ve picked 10 to 15 champions from our company, and that’s you.

The needNon-profits receive applications, but have no one to host or maintain them.
The missionAI agents that build an AWS platform from an application’s Git repository, then handle its maintenance.
A case studyPM Lab Solidaire (Next.js front-end, FastAPI API, PostgreSQL, file storage, and access to a model).
The visionAWS services with optimized costs, to make them accessible to any non-profit organization.
The goalMinimize human intervention: use managed services as much as possible, otherwise delegate to an AI agent depending on the problem encountered. A human is alerted only when the AI agent meets a task it cannot handle or has failed.

Exaltemps Solidaire est un hackathon à vocation sociale : livrer de vrais travaux IT à des associations sans aucune expertise informatique. Nous avons choisi 10 à 15 champions dans l’entreprise, et c’est toi.

Le besoinLes associations reçoivent des applications, mais personne pour les héberger ou les maintenir.
La missionDes agents IA qui construisent une plateforme AWS à partir du dépôt Git d’une application, puis en assurent la maintenance.
Un cas d’écolePM Lab Solidaire (front Next.js, API FastAPI, PostgreSQL, stockage de fichiers et accès à un modèle).
La visionDes services AWS avec un coût optimisé, pour les rendre accessibles à toute association.
L’objectifRéduire au minimum l’intervention humaine : utiliser des services managés au maximum, sinon déléguer à un agent IA en fonction du problème rencontré. Un humain n’est alerté que lorsque l’agent IA rencontre une tâche qu’il ne sait pas traiter ou qu’il a échoué.

PM Lab Solidaire, the application to host.

PM Lab Solidaire, l’application à héberger.

The workflow: squads of consultants work on a project for a non-profit organization, guided by a “Maestro” and an AI running in the background.

Today: in production at pmlab-solidaire.exalt-lab.com, hosted on a VPS.

Data: squad responses are stored in a database, while photos and audio from pitches are saved as files.

Dependencies: access to an AI model (via a LiteLLM proxy) and ElevenLabs text-to-speech synthesis.

Track one: the builder agent

Piste 1 : l’agent bâtisseur

Your agent calculates and builds the Terraform modules, then provisions the right AWS components for the application’s needs. You also build the harness around it.

  • Don’t waste time fetching the Git project with the agent.
  • Launch the agent directly on the local repository you already cloned.

Save your time for the architecture and the harness, not for plumbing.

Ton agent calcule et construit les modules Terraform, puis provisionne les bons composants AWS selon les besoins de l’application. Tu construis aussi le harnais qui l’entoure.

  • Ne perds pas de temps à faire récupérer le projet Git par l’agent.
  • Lance l’agent directement sur le dépôt local que tu as déjà cloné.

Garde ton temps pour l’architecture et le harnais, pas pour la tuyauterie.

Track two: the self-maintaining agent

Piste 2 : l’agent auto-maintenu

Your agent only steps in when an event isn’t handled by a managed service.

  • It must be able to create the monitoring and notification foundation, based on what the builder agent deploys.
  • It’s up to you to build the harness properly.

Ton agent n’intervient que si un événement n’est pas géré par un service managé.

  • Il doit pouvoir créer le socle de monitoring et de notification en fonction de ce que déploie l’agent bâtisseur.
  • À vous de construire le harnais correctement.

If the agent can’t handle a case or fails, a human steps in with a notification.

Si l’agent ne peut traiter un cas ou échoue, on passe à l’humain dans la boucle avec une notification.

Rules to ensure a platform’s success: a generic harness

Les règles du succès : un harnais générique

1 · Parameters, not hard-coded rules

Specific to PM Lab: the same agent serves the next association.

2 · Managed services first

An AWS service that restarts on its own is better than an agent. The agent handles the rest.

3 · A human in the loop

A written list of actions permitted for the agent. Anything outside this list triggers an alert to a human.

4 · Everything is tested

Terraform, agents, and harnesses. An autonomous platform proves itself.

1 · Des paramètres, pas des règles en dur

Spécifique à PM Lab : le même agent doit servir la prochaine association.

2 · Services managés d’abord

Un service AWS qui redémarre tout seul vaut mieux qu’un agent. L’agent gère le reste.

3 · Un humain dans la boucle

Une liste écrite des actions autorisées pour l’agent. Tout ce qui sort de cette liste déclenche une alerte vers un humain.

4 · Tout est testé

Terraform, agents et harnais. Une plateforme autonome fait ses preuves.

Test it, then launch everything in one go

Teste, puis lance tout d’un seul coup

With two agents, don’t run two separate setups. Wire them behind one command and one common harness (shared parameters, one list of permitted actions, shared logs). Then run it from scratch, as the association would.

Terraform

Format and validate, lint, security scan (Checkov or tfsec), plan checks, and a cost estimate against your budget.

Agents

Mocked AWS calls, then scenarios: a stopped ECS task, a failing database, an unknown error that must end in an alert.

Harness

An action outside the permitted list is blocked and escalated; the same parameters file works for another association.

End to end

Deploy in a clean account, reach the app URL, check the monitoring page, then destroy cleanly.
